# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

mondex is a competitive Pokémon dex (in the spirit of the Smogon and Showdown dexes): a Vue 3 + TypeScript + Vite SPA, deployed to GitHub Pages at `https://kpagcha.github.io/mondex/`. It currently has the type chart (`/types`), the type matchups page (`/types/matchups`: a Pokémon's types defending and a moveset attacking, side by side on wide screens, with `/types/matchups/def` and `/types/matchups/atk` for one side; `/types/calc` redirects there), a spaced-repetition type quiz (`/types/quiz`) a settings page (`/settings`: theme, language) and a credits page (`/credits`, linked from the footer), in English and Spanish.

## Commands

```sh
npm run dev         # dev server (base path `/`), also on the LAN for testing on a phone
npm run build       # vue-tsc type-check + production build, in parallel (base path `/mondex/`)
npm run lint        # ESLint (lint:fix to autofix)
npm run format      # Prettier (no semicolons, single quotes, 120 columns)
npm run gen-data    # regenerate src/data/generated/ (add `-- --update` to repin the sources to their latest commits)
```

The `justfile` wraps these for the user (`just dev`, `just dev-profile`, `just build`, `just preview`, which builds and then serves the production site at `http://localhost:4173/mondex/`, `just gen-data`); keep it in sync when scripts change.

There is no test suite, and none should be added. Verify changes with `npm run build` plus checking the app in the browser. The pre-commit hook (simple-git-hooks + lint-staged) runs `eslint --max-warnings=0` and Prettier on staged files, so any lint warning blocks a commit. CI (`.github/workflows/deploy.yml`) runs lint + build on every push to `main` and deploys, copying `index.html` to `404.html` so deep links work.

## Architecture

- **`src/data/types.ts`**: the Gen 6+ type chart, stored as a sparse attacker→defender map (pairs left out are 1×), exposed through `chart(atk, def)`. `iconUrl` gives the Showdown sprites the dev-only `pixel` style loads by URL; the default style's badges use the Bulbagarden Archives glyphs (`src/data/typeGlyphs.ts`). `TypeId` is the canonical type key everywhere.
- **Generated data (`src/data/generated/`)**: written by `scripts/gen-data.ts`, never edited by hand. It loads Pokémon Showdown's own code (through jiti) from a sparse checkout of its GitHub repo at the commit pinned in `scripts/sources.json` (cached in `node_modules/.cache`), applies the Champions mod and the rules of the VGC format for `VITE_REGULATION`, and derives availability from the regulation's legal Pokémon (an ability is available when one of them can have it, a move when one of them learns it and the game has it, an item when the game has it). English names are Showdown's; every other locale's come from PokéAPI's CSVs, also pinned, at the language identifier `scripts/languages.ts` gives it (Spain's Spanish is `es`); nothing in the script is specific to a language. `scripts/overrides.ts` fills in by hand, per locale, the names PokéAPI doesn't have yet (it lags new releases), the ones it has outdated (renamed since), and names for entries the games don't name on their own (Showdown's per-mask Embody Aspects). The script stops and lists any name an entry of the regulation is missing. Bulbapedia is a place to check names by hand, never a data source: its text is CC BY-NC-SA. Use GitHub, not the npm packages (`pokemon-showdown`, or `@pkmn/dex`, `@pkmn/data` and `@pkmn/mods`): they ship the Champions mod but lag a regulation behind it, and the `@pkmn` ones have no format rules. The output is JSON, one entry per line: for abilities, moves and items, `<category>.json` (every entry and whether the regulation has it) and `<category>.names.<locale>.json` (names of the available entries only, the only ones shown), `available.json` (just the IDs of the available entries, per category: the compact part the app needs at run time), plus `source.json`, which records the commits, pages and format it all came from. App code imports the full `<category>.json` files only with `import type` (for the ID types, at no bundle cost); Vite's `json.namedExports: false` keeps each JSON module a single `JSON.parse`.
- **`src/data/dex.ts`**: the dex's categories (conditions, moves, abilities, items, plus `group` for groups of effects) with their IDs (abilities, moves and items from the generated data; conditions and groups list the IDs referenced so far), and `Ref`, the reference to an entry: a `kind` plus an `id`, as IDs are only unique within a category (Electric Terrain is a move and a terrain). Data mentions entries through the constructors (`move('soak')`, `condition('sun')`), never bare strings; `available()` hides what the current regulation doesn't have, from the generated data; nothing about availability is maintained by hand. Render a ref with `<DexRef :to>`, which is plain text until its category is registered in `PAGES` with a route name, and from then on a link. `src/data/typeinfo.ts` holds the interactions beyond the type chart, made of refs.
- **`src/lib/`**: pure logic with no Vue components. `typecalc.ts` (effectiveness, defensive profiles, coverage, multiplier formatting/CSS classes), `quiz.ts` (builds the quiz cards: "pick the multiplier" and "tick all types that apply"), `srs.ts` (SM-2 scheduling with Anki-style learning steps counted in answers rather than time; the deck is saved to localStorage under `mondex.quiz.v1`), `motion.ts` (shared `SPRING`/`FADE`/`PRESS` animation settings).
- **`src/views/`**: one lazy-loaded view per route (`src/router.ts`). Route `meta.titleKey` sets the document title. View state that should be shareable is kept in the URL query (matchup picks, the selected chart cell) and updated with `router.replace`.
- **i18n (`src/i18n/`)**: a small hand-rolled module, not vue-i18n. `en.ts` is the source of truth for `MessageKey`. Other locales are typed as `Record<keyof typeof en.messages, string>`, so a missing key is a compile error. Each locale also exports the official in-game names of the types (`types`) and of every referenced entry, per category (`names`, typed `Names`, so a missing one is a compile error too), except generated categories (abilities, moves, items), whose names come from the generated data for every locale. `refName(ref)` (`src/i18n/refName.ts`) names any entry; the generated names load on demand, one locale at a time (`loadDexNames`), and routes that show dex entries set `meta.dexNames` so navigation waits for them (a new page with `DexRef` needs it too, or its names fill in a moment late). Use `t(key, params)` for `{name}` placeholders, `tSplit` to render a component (e.g. a type badge) in the middle of a message, and `typeName(type)`. To add a language: create `src/i18n/<code>.ts`, add it to `LOCALES` (`src/i18n/locales.ts`, which the generator reads too) and `BUNDLES` (`src/i18n/index.ts`), give its PokéAPI identifier in `scripts/languages.ts`, and run `npm run gen-data`, which lists any names to add to `scripts/overrides.ts` (`refName` picks up the new name files on its own). The type-check fails until each of those has the language.
- **Theming**: CSS custom properties in `src/styles/main.css`. Light is the default; dark comes from `prefers-color-scheme` unless overridden by `:root[data-theme]` (set by `useTheme`). On top of light/dark there are two styles, set as `:root[data-style]` by `useStyle` and picked only in the dev settings (production always uses `retro`): `retro` (the default; `src/styles/retro.css`, square ink-outlined surfaces, hard shadows, and `TypeIcon` renders flat badges with the glyphs in `src/assets/type-icons/`) and `pixel` (the plain `main.css` look with Showdown sprites). `index.html` applies the saved theme and style before first paint. Multiplier colors are the `--m*-bg/fg` tokens, applied through `multClass()`. Components use `<style scoped>` plus the global tokens and utility classes.
- **Animation**: motion-v (`motion.*`, `AnimatePresence`, `layout-id`). Reuse the settings from `src/lib/motion.ts` so all animations feel consistent. `App.vue` wraps everything in `MotionConfig reduced-motion="user"`.
- **Tooltips**: the global `v-tip` directive (`src/directives/tip.ts`, tippy.js) replaces native `title`. `v-tip:group="..."` makes elements share one singleton tooltip that glides between them (used for table cells).
- **Env files**: `.env` (tracked) holds shared settings the build needs, such as `VITE_REGULATION`; `.env.development` (tracked) holds dev-server-only defaults; a gitignored `.env.local` is for personal overrides. Nothing secret goes in any of them, since `VITE_` values end up in the shipped app.
- **Profiling**: `VITE_PROFILE=true` (`just dev-profile`, or `.env.local`) turns on `app.config.performance` in dev, for Vue's per-component timings in the Performance panel. They inflate durations, so measure speed on `just preview` instead.
- **Dev-only**: the settings page's dev section (`src/dev/DevSettings.vue`: the style picker and font lab) and `src/dev/fonts.ts` (a lab for trying fonts through `--font-display`/`--font-body`/`--font-num`) are loaded only when `import.meta.env.DEV` is true and are left out of production builds.

## Conventions

- Import from `src` using the `@/` alias.
- localStorage access is always wrapped in try/catch, with the app falling back gracefully; keys are prefixed `mondex.`.
- Don't create or trace UI icons; the user picks icons themselves.
